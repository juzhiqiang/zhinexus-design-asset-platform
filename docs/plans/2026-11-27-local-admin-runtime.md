# 本地管理端运行链路修复

用户于 2026-11-27 要求全部修复本地登录后成员与权限、接入与配置不可用的问题，并授权完成后合并主分支、清理开发分支。

根因：开发启动只创建无状态默认登录器，未初始化已有的持久化账号、接入配置与 OIDC 服务；数据库已连接仍返回 503。

1. 用真实编译产物和隔离 PostgreSQL 补失败测试，覆盖成员/配置接口、重启持久化、停用撤权、生产拒绝开发模式。
2. 本地默认登录改用已有 LocalIdentityService、ManagedAccountsService、AccessSettingsService。首次启动仅在没有本地管理员时事务化创建；重启不重置密码、角色或停用状态。签名密钥使用已有数据库存储。迁移仍显式运行。
3. 开发例外仅允许非生产、绑定 127.0.0.1、固定回环 API/身份地址；HTTP 会话使用单独开发 cookie，保留 HttpOnly、SameSite 与精确 Origin CSRF 检查。生产 HTTPS、出站白名单与请求契约保持严格。
4. 本地授权通过现有 PKCE/nonce/单次授权码完成，管理端与画廊均经真实登录表单，固定回跳目标。前端仅增加配置匹配的精确回环回调，修正将所有 503 误报成数据库未连接的提示。
5. 执行窄范围真实 HTTP/数据库与浏览器验收，再执行工作区检查、构建、类型检查、单元测试和浏览器回归；新增独立验证记录。验证后提交修复、单独升平台 PATCH，合并 main 并删除本次开发分支，不推送。

不修改原始架构文件；本地验收不代表生产 OIDC/TLS 或业务试点验收。

全量回归发现的关联修复：

- 页面与外壳共用一次会话校验，失效时清理旧凭据；根路径登录后回到资产页，窄屏顶栏允许换行。
- 密码重置后同秒重新登录等待越过撤权时间边界，并再次核验账号状态，不放宽旧凭据撤销规则。
- 已启用预览配置允许本地服务重启；已激活正式 OIDC 配置仍拒绝默认开发身份。
- 手动截图关联导入清单中的真实示例与状态；异步文件读取只把本次新增内容合并到当前状态，避免覆盖同时导入的产物或其他截图。保留原始摘要核验与逐实现缺图阻断。
- CLI 新项目精确导出 API JSON 文件，消除通配导出与服务端严格路径校验的冲突。使用安装后的 juz 创建独立 React/Vue 项目，经过冻结、截图、真实三存储发布及恢复验证。
- 更新过时的浏览器定位、提示与隔离测试材料；测试等待具体导入完成消息，另用延迟文件读取稳定覆盖并发顺序。
