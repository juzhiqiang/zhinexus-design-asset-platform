# T17 双框架独立验收矩阵记录

日期：2026-11-19（Asia/Shanghai）。本记录覆盖矩阵定义、评分边界和封存校验；不把 synthetic 工程结果冒称真实业务验收。

## 当前交付

- 固定 20 个正向场景：Vue 10 个、React 10 个；整体和分框架最低通过门槛均为 80%。
- 强制拒绝独立计数、不进入正向分母；固定 13 个案例覆盖 peer 冲突、中途编辑、无候选、业务缺口、类型过但行为失败、版本/视觉不匹配、NEW/DIFF/环境不兼容、修复预算、链接路径、敏感 sentinel 与错误宿主。
- 每个正向 cell 绑定同一份冻结 CLI tarball 摘要和 SDK bundle 摘要，并要求计划、apply、验证规范、报告、生成文件、typecheck/build、loopback 资源、交互、截图与视觉基线证据。
- run-seal.json.files 只采信 evidenceRoot/files/ 根目录中的直接文件；receipt 路径必须与封存条目的文件名和摘要一致。
- 缺失、重复、未知、skipped、blocked、摘要不一致、越界写入或用户修改丢失均失败关闭。
- 评分器对缺少必需字段的正向 receipt 进行运行时结构检查；畸形数据记为失败，不会抛出异常或进入通过计数。
- runner.ts 固定迭代 20+13 个场景并调用注入的 scenario executor。异常单独留证据且不减少分母；运行前后核对冻结 tarball 字节摘要、已安装包名/版本/bin 路径；结束时要求宿主先停止自有进程，再用 payload.receipts[] = {caseId, kind, evidencePath} 调用 sealEvidence，最后从宿主封条重读证据并计算分数。
- frozenCliIdentityFromInstall 适配 T17 owned-host 的安装结果 root/entry/version/tarballSha256，并补有结构映射测试。
- 矩阵分支尚未集成 T17 host 实现和 CLI integrate verify/repair 入口，且缺少可用 API、Verdaccio、冻结 CLI tarball、SDK bundle 和视觉基线。因此 scenario executor 仍是显式注入边界，当前测试不能视为真实 CLI/Vue/React 运行结果。

## 场景冻结要点

- 正向 20：Vue V01–V10、React R01–R10，覆盖 npm/pnpm × standalone/workspace（V03/V04、R03/R04 为 workspace），折线/柱状/饼/散点/趋势卡/排名/占比、多实例、空数据→更新、隐藏→可见、KeepAlive（Vue 限定）、StrictMode（React 限定）、系列删减+渲染器切换、已知模板 recipe 修复后通过（V10/R10）。
- 每例都预声明 `readySelector`、动作、断言、交互计数前后值与视觉主题/渲染器；交互必须严格增长。
- 拒绝 13：N01 peer 冲突、N02 中途编辑、N03 无候选、N04 业务缺口、N05 类型过点击失败、N06 画面过版本不符、N07 视觉 NEW、N08 视觉 DIFF、N09 视觉环境不兼容、N10 修复预算、N11 路径链接、N12 敏感哨兵、N13 错宿主静态替身。

## 独立 observability（不依赖产品自证）

- 入口 import：要求宿主入口字节中真实出现对每个生成文件的 import 说明符，且清单与 `generatedPaths` 完全一致。
- `installedVersions` 与 `plan.exactDependencies` 必须逐项一致；缺任何一项或依赖守卫非 passed 均判失败。
- 视觉判定与 manifest proof 分离：`NEW/DIFF/INCOMPATIBLE` 与精确 installed proof 互不替代，任一不过即不过。
- run-seal 与 score 引擎重算每个文件的 `sha256` 与 `bytes`，receipt 字节必须等于 `canonicalJson(receipt)`；篡改即抛错。
