1. **Windows 原生复验缺口**：T09 六种图表 + T09/T10 新增范围的 `.\scripts\verify.ps1` 全量原生验收始终未执行；柱状图 / 散点 / 趋势卡片 / 排行榜占比四份清单的回填模板均为空。

4. **`README.md` SDK 段落自 G0 / T02 起过期**（仍写「包壳」「版本 0.0.0」「图表控制器尚待实现」），T09 全批次未触碰，建议 C 在 T09 收口统一刷新——至 2026-11-13 仍未处理。
5. **折线 / 柱状模块注册与覆盖白名单不一致（既有边界）**：折线未注册 `Legend` / `Title`、柱状未注册 `Title`，而其 `optionOverrides` 白名单允许这些键；为避免影响既有产物体积基线与冻结历史未改动，已建议 C / B 在 T09 收口统一评估，本主题内未见后续处理记录。
6. **`charts-core` / `charts-react` 的构建不清空 `dist`**：`tsc` 不会删除已消失入口的产物，历史构建残留会直接进 tarball（疑为饼图两处 tarball 摘要相差 32 / 36 字节的成因，未定位到确证）；建议给这两个包补清理步骤（`charts-vue` 的 `scripts/build.mjs` 已有清理并注释原因）。
7. **候选 tarball 摘要的取法纪律**：必须用发布链自身方式（`packages/component-cli/src/local/pack.ts` 的 `packPackage()`：`pnpm pack --pack-destination` + `SOURCE_DATE_EPOCH`）或在 `git archive` 取出的树上打包；`tar` 同步工作树会把 `0700` 模式带进 tarball 导致摘要偏离（trend-card 篇为此发过摘要勘误：30,260 / 5,692 / 10,296 为错误值，正确为 30,254 / 5,686 / 10,300）。SDK tarball 并非冻结工件，冻结工件是 B / C 的 `tests/fixtures/releases/**`。
8. **空数据 + 控制器重建不创建画布**：zrender 在无可绘制内容时不创建画布，`single-instance` 与 `renderer-match` 自检会失败；示例测试用「先经 `solid` 中转」规避，未放宽 `collectChecks`（放宽会改变 B 的 CLI 依赖的协议语义，需先与 B 对齐）。
9. **图表能力边界**（各批显式不提供，均未在后续批次补齐）：柱状图无横向柱状与柱宽 / 圆角配置；饼图无 `roseType` / `minAngle` / 自定义内半径与环形间距，负值直接抛 `ChartDataError`（如需展示盈亏构成须在 core 增加显式正值化或正负分栏，不得静默取绝对值）；散点图无 `symbolSize` / `symbol` / `itemStyle` 与数值轴 `min` / `max` / `scale` 字段，x 轴标签固定 0 位小数无单位；趋势卡片数值摘要基于固定卡片高度（示例 `360×180`）像素定位，宿主任意缩放不保证像素级一致，未做 sparkline 开关、聚合口径与多指标并排；排行榜与占比只接受单系列且条目名唯一（多系列抛 `ChartDataError`，`path: 'series[1]'`），需要多条目多分组应新增场景而非放宽守卫。
10. **大小写敏感文件系统的构建未验证**：`ranking.ts` 与 `RankingChart.tsx` 只差大小写，NTFS 上已按 `RankingChart.*` 命名规避（`TS5056` 坑），大小写敏感文件系统未实测；沙箱内改名后必须 `rsync -a --delete`（排除 `.pw-browsers`）清理旧文件再全量重建，否则产出被拼接的损坏 `dist`。
11. **示例就绪探针对「渲染结果相同」的状态对失效**：占比 `zero-total` 与 `empty` 都无系列、都显示「暂无数据」，系列快照不变化会让 `arm()` 超时，fixture 让这两个状态各自从 `default` 单独进入；后续批次写 fixture 须遵守同一约束。
12. **`pointClientPosition` 的扇形几何回退依赖 zrender 内部结构**（显示列表 `type === 'sector'`、系列顺序），ECharts 升级（T10）若改变该结构，兼容矩阵会暴露；zrender 散点符号元素类型是 `path` 而非 `symbol`。
13. **真实三存储闭环在 A 侧未执行**：Verdaccio / PostgreSQL / MinIO 完整发布链路只由 C 在隔离环境完成（三存储发布 READY + 逐预览/截图摘要）。
14. **共享工作树纪律相关遗留**：空合并事故 `1161e03` 已进入 main 历史（其上叠了 T06 工作，不做历史重写）；`feat/t04-t06-release-registry` 尖端 `0560a19` 未经由 main 合入，待 branch 所有者确认；`feat/t09-trend` / `feat/t09-trend-merge` / `feat/t09-trend-main` 三个分支与三个 scratch worktree（`outputs/t09-main`、`outputs/t09-merge`、`outputs/t09-trend`）待仓库负责人确认清理；多处合并明确「未 push，需用户显式授权」。
