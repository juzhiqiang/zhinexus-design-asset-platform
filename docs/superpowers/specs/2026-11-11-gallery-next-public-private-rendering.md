# 画廊公开发现与私有工作区设计

## 意图

组件画廊需要让已批准公开的组件资料能够被普通访客和 AI 搜索抓取，同时保留登录后才能访问的发布与团队操作。用户确认按页面及数据范围区分公开和登录内容，不拆分成两个独立前端应用。

## 目标

- 将现有 `apps/gallery` 从 React + Vite 客户端壳调整为 React + Next.js App Router。
- 为公开发现页提供静态生成或按需重新验证的宿主能力，输出可直接读取的正文和页面元数据。
- 为登录工作区预留独立路由组；未来接入 OIDC 后由服务端会话和 API 权限共同保护。
- 公开页面只读取服务端明确公开的目录 DTO；默认不公开，私有字段、令牌和用户态数据不得进入静态 HTML、共享缓存或公开 metadata。
- 保留现有独立 NestJS API、预览网关、Vue/React 组件 SDK 与工作区成员数量。

## 非目标

- 本次不建立 OIDC 登录、会话或角色授权；这些仍由 T05 提供。
- 本次不实现真实组件目录、详情、上传、发布任务或隔离预览；这些仍按 T07/T08 和 G2 的依赖验收。
- 不新增第二个画廊应用，不改变 Vue/React 组件双框架支持，不修改原始架构规格。
- 不将搜索排名或 AI 引用作为可保证结果；本次只提供可抓取的渲染基础。

## 页面与访问边界

- 公开路由采用 `(public)` 路由组；后续组件目录、分类、组件详情和公开文档可以按构建时静态生成或 ISR 输出。
- 私有路由采用 `(console)` 路由组；上传、发布记录、任务和团队资料在 T05 完成前不实现可用页面。接入后必须按请求校验会话与授权，设置 `noindex`，并禁用共享公开缓存。
- 登录墙不包住公开详情整页。目录服务只返回获准公开的 Ready 资产以及允许公开的最小字段；未在公开 DTO 中的数据一律视为私有。
- 公开页面上的私有操作可以引导登录，但服务端/API 必须再次鉴权；仅隐藏客户端控件不算访问控制。
- 本次没有真实目录契约或 Ready 资产，公开入口只保留诚实的空状态，不使用伪造组件或兼容性信息充当索引内容。

## 技术选择

- 单一 `apps/gallery` 使用 Next.js App Router，保持 React 19 与现有 TypeScript/pnpm/Turbo 工作区。
- 采用 Node 运行时托管 Next，以保留静态公开路由、ISR 和未来服务端会话检查的组合能力；静态导出不是目标。
- 公开目录数据必须来自独立的公开 API/DTO；用户态 API 请求不得被共享缓存。T07 冻结目录契约后再确定公开数据标签与重新验证触发。
- 生成 metadata、canonical、sitemap 和结构化数据只适用于实际公开路由；私有工作区统一 `noindex`。

## 构建者决定

- 仓库内沿用 `apps/gallery`、端口 `5173` 和根工作区版本策略。
- Next App Router route group 不改变 URL；按现有验证模式保留 build/typecheck/browser 三类检查。
- 迁移基础工作不得标记 T05/T07 或 G1/G2 完成，也不得把 Next 的框架渲染等同于 GEO 排名提升。

## 仍待后续确认的输入

- G1/T07 冻结公开目录 DTO 与资产公开审批/撤回流程；在此之前公开页面不展示真实组件数据。
- T05 冻结 OIDC session cookie、角色检查与登录后回跳契约；在此之前不宣称私有路由已安全授权。
- 部署计划为 Next Node 服务提供运行时、域名、TLS 与健康检查；本次仅保证本地构建和运行入口。
