# 自主管理的平台账号与权限后台设计

日期：2026-11-22，Asia/Shanghai。状态：待用户确认的设计；尚未实施或安装身份服务。

## 1. 用户意图与当前事实

用户没有现成的公司统一登录、部署服务器或域名，希望账号与访问权限能够由后台管理。用户要求继续整理方案。

当前平台已经实现 OIDC 网页/CLI 登录、部署登记的管理员身份、接入配置版本、角色限制、停用主体、组件/包 ACL 和逐请求预览权限检查。现有“接入设置”不提供成员账号创建、密码重置或可视化 ACL 管理。测试中的隔离身份源不是可长期使用的账号服务。

本设计让管理员在资产平台内创建成员、设置角色与资产权限、停用/恢复账号、重置密码、强制重新登录，并查看操作记录。成员从平台入口使用用户名和密码登录。账号归本平台自行管理，无须先有外部公司 SSO。

## 2. 本轮技术选择及范围决定

以下是执行方建议，用户尚未逐项确认：

- 自托管 Keycloak 作为身份服务；保留已有 OIDC、Web Cookie 会话与 CLI PKCE，不新增平台自行保存密码或直接交换密码的认证协议。
- 日常管理入口在资产平台的“用户与权限”后台。Keycloak 管理服务凭证仅由 API 持有；成员和浏览器不持有该凭证。
- 管理员创建账号；第一版关闭公开注册，无 SMTP 依赖。用户名不要求公司邮箱，显示名可为中文。
- 平台超级管理员由部署初始化并按 issuer + subject 登记；第一版后台管理普通成员，不提供任命超级管理员、修改部署信任边界或删除管理员的 HTTP 接口。
- 与原“公司 OIDC”要求的差异是身份源由平台自行维护。认证协议不变；用户确认后在实施评估及计划中追加此范围决定，不修改原始架构文档，也不追改历史验证结论。
- 本机试用使用真实身份服务、持久化存储和可信 HTTPS IP 入口。正式部署依然需要持久化、备份、TLS、权限与撤权实测；本机账号不自动替代正式环境验收。

不新增工作区成员。身份服务属于 infra；API、网关、画廊与 contracts 按既有职责维护。

## 3. 管理员和成员的使用方式

管理员先登录平台，再进入“用户与权限”。列表支持用户名/显示名检索、启用状态筛选和分页；显示用户名、显示名、角色、账号状态及身份同步状态。

创建账号时输入用户名、显示名，选择 reader/publisher/maintainer，可选具体组件与包授权。用户名按 ASCII 小写规范化后在本身份源内唯一，创建后不改名；显示名可以修改。执行方默认用户名规则为 3–64 位字母、数字、点、下划线或连字符，首位为字母或数字。重复用户名返回 CONFLICT。

账号创建成功后由管理员设置临时密码。密码通过 HTTPS 瞬时提交给 API，再发送身份服务；不存入平台数据库、作业正文、日志、浏览器持久化存储或报告。身份服务保存密码凭据，平台不支持读取原密码。临时密码必须在首次登录时修改；密码策略由受控 realm 模板统一设置，执行方默认至少 14 字符。

创建和设置密码是两个明确步骤。未设置密码的账号显示“待设置密码”，不允许成员登录。密码重置网络结果不确定时显示“待运维核实”，不向用户报告成功，也不以后台重试保存密码。

用户详情提供修改显示名、修改业务角色、修改组件/包权限、停用、恢复、重置临时密码和强制重新登录。第一版停用代替物理删除，保留发布/审计归属，不复用已创建的身份主体。

成员点击平台登录按钮，进入自托管身份服务的用户名/密码页面，完成首次改密后返回资产平台。CLI 沿用 component login 的浏览器登录和固定本机回环。第一版不开放用户自助注册、邮件找回和身份服务的普通用户账号管理后台；后续自助改密需另补会话撤销流程。

## 4. 权限规则

角色沿用 reader、publisher、maintainer，并保留组件与包的精确 ACL。角色允许组合；角色不是全资产权限，不自动授予通配组件或所有 npm 包。

新账号默认 reader，但没有私有组件或包的授权。显式授予后才能读取对应私有资产；发布必须同时满足角色、组件 ACL 和包 ACL。公开目录保持现有公开规则。

后台成员管理仅接受已登记的平台管理员身份。maintainer 不因业务角色取得后台权限。部署登记的管理员账号不能经成员管理接口停用、删除、重置密码、撤销全部会话或修改角色；管理员本人的密码和失锁恢复走部署身份服务运维流程。该限制在 API 强制执行。

所有管理变更校验当前 OIDC 配置代数、管理员状态、目标账号版本和预期修订。Cookie 写请求继续核验画廊 Origin；不得只在页面隐藏操作。并发旧版本提交返回 CONFLICT，失败和成功均留下脱敏审计。

## 5. 账号状态与即时撤权

平台 PostgreSQL 保存管理目录及授权，身份服务保存登录凭据。自主管理的 issuer + subject 对应唯一平台主体，不按同名用户名自动关联历史用户。现有外部 issuer 的用户和授权保持原路径；新增管理接口只操作部署登记的自管 issuer/realm，禁止按前端提交的任意 issuer 调用身份管理 API。

每个自管账号具有 desiredRevision、accessEpoch、同步状态及明确的启用/停用状态。角色、ACL、密码重置、停用、恢复和强制重新登录均增加该账号 accessEpoch，使已有 Web session、CLI token、候选票据、preview grant 和 preview session 失效。恢复后必须重新登录，不能让停用前的凭据恢复权限。

认证端保留并核验 JWT 中受签名保护的账号版本，以及 iat/auth_time；Web session 和预览授权保存签发时的账号版本。身份服务受控 mapper 将管理员专属只读用户属性映射为 platform_account_version，且 access token 输出 auth_time。用户不能经个人资料修改此属性。自管账号缺少版本或必要时间声明时失败关闭。

平台按本地最新版本、签名版本和最新授予的角色共同验证权限；不能把旧 JWT 的角色视为永久授权。版本变化同时推进认证时间下限，旧 SSO 会话/refresh 所签发的令牌即使带上新版本也不能恢复使用。时间下限记录为 max(旧下限, 数据库提交阶段的当前整秒)，签名 auth_time 必须严格大于下限，iat 不得早于 auth_time；同一秒发生的新登录需在下一秒重新认证，不能放宽为大于等于。自管登录强制新认证；mapper 和首次改密链路必须以真实 Keycloak 测试确认，不用 JWT 最终过期替代撤权。

账号版本声明使用十进制字符串，与 PostgreSQL bigint 一致，不经 JavaScript 不安全整数转换。Web session 从经过验证的同一主体 token 保存版本和 auth_time；候选登录、CLI 和预览也必须核验对应版本，禁止从未验证的 JWT 解码或请求体补填声明。自管 issuer 下未登记的主体（包括遗漏导入的管理员）默认拒绝，bootstrap 负责首个管理员的目录登记。

安全收紧操作先在平台数据库事务中提交撤权与审计，再进行身份服务更新和会话登出。身份服务不可用时本地拒绝继续有效，页面显示“平台已撤权，身份同步待完成”。创建、恢复和权限扩大在远端同步、版本及必要配置核验完成后才可启用；不能因为请求已排队就开放权限。

恢复可登录状态前，必须确认远端会话登出与账号版本更新完成，再于本地最终启用事务推进认证时间下限至该阶段的当前整秒。在同步期间取得的 token/会话也不能复活；成员须在最终启用后的时间边界之外重新认证。角色/ACL 变更和密码重置同样遵守此顺序，不仅在操作开始时设置一次时间下限。

API 每次受保护请求及业务写事务、网关每次授权兑换和资源请求均核验账号状态/版本。写事务与账号变更通过共享/排他账号行锁协调，防止认证后权限已撤销仍提交写入。网关仅取得必要只读账号状态与版本权限。

撤权承诺边界是平台事务提交后开始的受保护请求；已传输到浏览器的字节不回收。测试分别记录提交时刻、各路径首次拒绝时刻及请求结果。生产目标时限后续由部署负责人确认，不能把本设计的机制描述当作真实实测证据。

## 6. 身份服务同步与故障处理

账号创建、角色/启用状态变更通过单独的持久化身份操作记录协调，不混入 release_jobs。操作正文只包含非密码字段、主体、期望修订和账号版本。按单个账号串行处理，处理进程独立于请求生命周期，重启可恢复。

网络 I/O 不占用数据库事务。先保存期望状态及需要的本地拒绝，再调用远端，最后核验远端实际主体、角色、启用状态和版本，使用最新修订/租约完成本地状态转换。远端不提供本地 fencing token 原子保证；不确定和旧操作的结果不能放行账号，必须基于最新期望状态重读并收敛。账号版本不匹配时拒绝认证。

创建前先在平台登记随机管理账号 ID，远端请求携带只允许管理员设置的 platform_managed_user_id 属性。创建远端用户后发生响应丢失时，只能接受用户名和该属性均与当前操作一致的主体；同名但属性不匹配的已有用户返回 CONFLICT，不能接管或自动导入。初始账号保持不可登录直至目录、角色、版本与密码设置完成。

密码设置走独立的受保护瞬时操作，不把密码写入持久化队列。操作前增加账号版本并撤销会话；只有身份服务明确确认、且当前操作修订仍匹配后显示“密码已重置”。平台只持久化是否已设置凭据及操作状态，不保存密码。网络结果不确定时保留本地拒绝，显示“待运维核实”，不直接重试或并发接受新密码设置。须经受控运维核对旧请求已经完成后，再由管理员发起新的密码设置；租约到期本身不证明远端密码操作已停止。此项恢复流程及首次改密后的登录证明纳入实施验收。

客户端只获得已脱敏的管理结果和同步状态；不会显示远端响应正文、密码、token 或密钥。常规管理必须经资产平台执行；直接修改身份服务属于受控运维操作，需要同步核对后再开放账号，不假称已实现任意外部身份源的自动同步。

## 7. 初始化、本机试用与恢复

增加独立且持久化的本机试用栈，使用新 Compose 项目、专属端口/卷和私有凭据目录，避免复用当前凭据缺失的共享 G2 栈。所有入口默认仅本机可达；初始超级管理员密码不使用固定默认值，不写 Git，也不打印到工具输出。

引导创建专用 Keycloak realm、独立 Web/CLI 客户端、业务角色/claim mapper、API audience、首个管理员和管理服务账号，执行平台迁移，并登记管理员 issuer + subject。bootstrap 仅在空的自有栈首次执行；发现已有数据但凭据丢失时拒绝覆盖，走恢复流程。

身份管理连接限制为部署允许的固定 realm/HTTPS 地址、可信 CA 与 DNS/CIDR；禁止重定向和任意 URL 输入。管理服务账号只授予该 realm 必需的用户/角色管理权限，不使用 master 管理员令牌作为平台运行凭据。

首次试用可以使用当前 Windows 电脑及同 IPv4 分 HTTPS 端口模式，无须公网域名。提供从初始化到管理员登录、创建成员、成员登录、授权发布、查看预览、停用和恢复的明确启动/验证步骤。TLS 证书须覆盖实际访问的 IP，客户端须信任 CA；不关闭证书校验。

超级管理员丢失密码或服务凭据时仅使用部署侧恢复，不新增免认证 HTTP 运维后门。备份覆盖平台数据库、身份服务数据库及部署密钥的受控保管；恢复后重新核对账号版本和失效凭据，不清理共享持久卷。

Keycloak 具体版本、镜像 digest、部署最小权限细节和 realm 配置在实施计划阶段按官方来源固定并实测；不在当前设计阶段安装或假定 latest 标签可用于交付。

## 8. 契约、文件范围与验证

C 维护 packages/contracts 的管理 DTO/运行时校验、API 账号管理和身份适配/操作处理器、数据库迁移、网关只读版本核验、infra 与根脚本。B 维护画廊用户管理页面/客户端、导航、登录文案和浏览器验收。顺序收口公共契约，不覆盖已有工作区修改。

实施前更新实施评估和新增执行计划；公共契约先对齐。OIDC 协议和已有 client 登录路径保持兼容，用户可见“公司登录”文案在自管部署中显示为“账号登录”，不将旧历史证据改称本次验证。

验证包含：
- 契约反例：重复/非法用户名、非法或通配授权、额外字段、密码泄漏、过期版本、管理员目标操作、非管理员请求。
- 真实身份服务 + PostgreSQL 集成：创建、首次改密、Web/CLI 登录、角色与组件/包 ACL、停用/恢复、密码重置、强制重新登录及已持有凭据拒绝。
- HTTP/网关并发：权限变更与写事务竞争，旧代数/账号版本拒绝，恢复不复活旧授权，两个独立服务看到相同最新状态。
- 故障恢复：身份服务停机、超时/响应丢失、同步进程重启、重复创建、旧修订覆盖、密码结果不确定；本地撤权不被远端失败抵消。
- 本机浏览器：管理员完整成员管理、非管理员拒绝、首次改密回跳、Vue/React 预览及旧授权撤销；浏览器只在开发者电脑运行。
- 变更对应构建、typecheck、窄范围及必需集成回归、工作区服务闭包检查。实施达到 feat/fix 发布条件后按规则单独升级受影响包版本及 CHANGELOG。

本设计交付只检查文档链接、diff 和受保护文件摘要，不运行产品测试来冒充账号后台已经实现。正式部署验收、公司部署责任与双业务试点继续独立记账。
