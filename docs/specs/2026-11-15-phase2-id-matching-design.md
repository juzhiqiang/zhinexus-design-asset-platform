# 二期设计 ID 匹配范围调整

## 用户决策

2026-11-15 用户明确当前规划不需要大模型，设计将按对应 ID 规则匹配；随后确认 ID 规则还没有定。本决策覆盖原计划 T13/T14 的模型与多模态要求，原架构文档与历史验证记录保持原样，不改变三期范围。

## 交付方向

复用 ProjectContext、发布目录、精确版本、权限/兼容过滤与文本发现能力。设计 ID 经显式配置得到精确发布身份，再由服务端验证资格，最后结合真实 API/示例生成装配方案。文本相似度不能覆盖配置，不推断数据接口、事件函数或布局。

由实施方选择的首版形式（不是用户已确定的设计命名规范）：

- `DesignIdMappingV1 = {schemaVersion:1, ruleSetId, revision, entries}`；ruleSetId 与 revision 均为非空字符串。
- 每项 `{designId, framework:'vue'|'react', variantReleaseId}`；同一 designId 可分别配置 Vue/React，不能重复同一 designId/framework，即使目标相同也拒绝。
- `DesignElementV1 = {instanceId, designId}`。实例 ID 在一次输入内唯一；多个实例可以引用同一 designId。
- `DesignIdInputV1 = {schemaVersion:1, mapping, elements}`。允许空配置/空元素列表表示尚未配置，不能称为匹配成功。
- ID 为不透明字符串，保留原值精确比较；不切分、不自动 trim、不转大小写、不解释为正则/路径/脚本。首版沿用契约 text 的非空/2048 字符上限与 JSON 预算，不增加业务命名限制。
- 规则修订由配置提供，仅作溯源，不能独自证明内容不可变；配置变化必须使旧匹配结果失效。

契约校验通过不代表发布存在、可访问、Ready 或兼容。服务端仍须复读真实权限与发布状态，不能向无权限调用者泄露目标细节。

元素引用未知 designId 或缺少当前框架映射时，输入结构仍可通过，后续解析返回对应实例的缺口；不能当作非法 JSON 或猜测替代组件。重复映射和重复实例由契约拒绝。

## 分工和未覆盖边界

首个子任务只交付配置/元素清单契约与校验，不据此宣称 HTTP 匹配或装配已经交付。随后 C 实现发布定位、MatchPlan 和真实材料校验；B（Claude 桌面端）在契约冻结后实现配置/清单输入与方案界面；A（Antigravity）维护反例并独立审查 API/框架映射。保持独立 worktree 与文件所有权。

实际 ID 命名/命名空间、设计平台导出格式、规则维护方与真实样本尚未提供。先保留配置入口，具体设计连接器待实际格式确认，不虚构支持。截图可作展示附件，本期不做 OCR、模型区域识别或视觉匹配。

## 验收

契约覆盖未知字段、错误类型、非法框架、重复映射/实例、多实例复用、两框架区分、空配置和不透明 ID；JSON Schema 与运行时额外唯一性规则分别说明。行为按 TDD，生成 schema 并校验，公共包修改执行全图验证。

后续 HTTP/装配覆盖未知 ID、冲突、错误/废弃/不可读目标、peer 不符、撤权、缺 API、配置变更后的旧响应。规定测试集精确映射正确率 100%，误装配和权限/框架/版本硬违规 0；合成与真实样本分别报告。原视觉 30 样本、Top-5 和模型超时不再是本期门槛；真实设计规则尚未到位时完整 T14 保持待验收。
