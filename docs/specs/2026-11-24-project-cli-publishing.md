# 真实项目 CLI 发布与组件分类

2026-11-24 用户确认：组件由真实项目开发者实现，优先完成 CLI；同时允许平台仓库开发，后台预先维护分类，发布时选择 Vue / React 与所属分类。历史版本不可变并可精确消费；Zip 手动入口与低代码元数据保留后续接入。

## 本轮交付

- 独立项目通过 `component.config.json` 登记已有组件包、框架实现、公开导出、API/文档与独立消费者示例，不生成业务组件。
- `component init` 初始化接入配置；`component dev` 执行开发者显式配置的本地开发命令；`component doctor` 在构建前检查配置、文件、身份与发布权限。
- `component release` 有项目配置时完成本地构建、冻结、工作区外消费者安装/构建/截图、材料校验与上传；已有 Bundle 模式及旧 SDK 准备入口继续可用。中断重试使用原冻结材料，不重新打包。
- 管理员创建、重命名和启停分类；发布者只选择启用分类。分类使用稳定标识，不物理删除历史分类。
- 发布材料记录分类选择；API 校验分类存在且启用、框架与实际包/导出一致及原有组件/包授权。同一逻辑组件的不同实现归属于同一分类；历史发布材料保留当时选择。
- 分类不授予资产访问权，不改变公开/私有状态。继续使用管理员预登记组件及包 ACL，无自动通配授权。

2026-11-24 联调补充：框架选择只能选择材料中实际存在的实现，并遵守既有 npm 包完整性校验。同一冻结包版本的 JavaScript 子路径须完整申报，管理端按包联动选择，不能裁去同包的其他实现或重新打包。需要单独发布 Vue / React 时，开发者使用相应独立组件包；一个包同时包含两框架时须提交完整实现材料。

## 项目接入边界

支持独立组件包及真实项目中的组件子包。业务应用本身若 `private:true`，须选择明确的可发布组件子包；不得把整个业务工程当作组件发布。配置是 JSON 数据，本地命令采用程序与参数数组，不把上传配置交给服务器执行。

每个发布实现必须提供可运行消费者示例及 `window.__COMPONENT_EXAMPLE__` 就绪协议。消费者必须位于工作区外，安装冻结 tarball，拒绝源码 alias、workspace 链接和任意依赖安装脚本。真实 Vue/React 实现分别验证。示例、文档与 API 由开发者维护，CLI 不伪造组件能力或兼容记录。

2026-11-24 审查补充：组件 build/dev 继续执行开发者显式配置的本地命令；发布验收消费者限定为 CLI 控制的 Vite 适配器，加载消费者实际安装的精确 Vite 版本及其配置。CLI 检查真实模块解析来源，并在所选冻结导出的框架实现实际执行时记录使用；仅能 import、配置标签或开发者自填就绪身份不能替代此证明。临时消费者包装必须保留 Props、事件及 ref/就绪句柄语义，不修改冻结 tarball 或实际安装的组件文件。其他消费者编译器作为后续适配器，不承诺当前任意消费者构建命令均可验收。

## 协议与后续

配置描述协议与资产 `ReleaseManifestV1` 分开。发布清单只增加可选分类字段，保留旧材料读取；新项目发布要求明确选择分类。可选的未来低代码配置/编辑器元数据不影响普通 npm 导入。

真实项目中的普通组件可以省略 `EnvironmentV1.echartsVersion` 与 `ComponentApiV1.styleExport/readyMethod`；字段提供时仍按原协议严格验证。环境报告只记录实际安装的 ECharts 版本；未使用图表引擎的组件不生成 ECharts 兼容记录（`compatibility: []`）。消费者就绪协议仍必需，与组件是否暴露图表 ready 方法独立。

已有图表自动装配协议保持其样式与 ready 元数据要求；普通组件缺少该元数据时匹配接口明确返回 `API_UNSUPPORTED` 缺口。发布和普通 npm 导入不依赖自动装配资格，通用低代码接入另行交付。

后台 Zip 只承载预构建材料，仍强制手动截图来源；服务器严禁组件构建、代码执行或截图。历史版本下载与页面版本绑定为后续独立交付，不把已有精确详情查询宣称为完整下载功能。

## 验收

使用测试夹具模拟开发者已提供的 Vue/React 包，不新增平台业务组件。证明独立安装 CLI 能处理工作区外项目；覆盖构建失败、私有应用误发布、框架错配、缺图、未知/停用分类、无权限、源码链接、产物篡改与中断恢复。后台分类变更通过真实 HTTP 持久化和浏览器交互验证。最终运行全图类型/构建、工作区检查与根测试，记录外部设施未覆盖项。
